# chip-ref-ds3231：XSim 实测 I2C RTC 从机寄存器语义（地址应答、指针自增、BCD 走时）

**对应教程**：<https://geek-doc.cn/chip-design/chip-ref/ds3231.html>

## 复现方式

需要 Vivado Simulator（本实验用 2017.4，Windows）：

```bat
xvlog tb_ds3231_i2c.v && xelab -debug typical tb -s sim_ds3231 && xsim sim_ds3231 -runall
```

仓库内 `xsim-i2c-register.log` 是本次实测的原始输出（六场景 6 行 MEAS 记录）。

## 实验设计

测试台由一个最小开漏 I2C 主机 BFM（SCL/SDA 三态 + 上拉）和一个 DS3231 行为级从机模型组成：7 位地址 0x68、寄存器文件 0x00–0x12、BCD 码 1Hz 走时、寄存器指针自增并在 0x13 处回卷到 0x00、温度寄存器 0x11/0x12 只读。六个场景各出一行 MEAS：

1. **bus_scan**：遍历地址 1–127 发写地址，统计 ACK/NACK，验证只有 0x68 应答。
2. **time_write_readback**：写秒/分/时三个 BCD 时间寄存器，重设指针后经重复 START 读回比对。
3. **wrong_addr**：向 0x69 发起写事务，验证 NACK 且寄存器文件不被改动。
4. **ptr_wrap_ro**：从 0x10 连续写，验证 aging 寄存器可写、温度寄存器写被忽略、指针越过 0x12 后回卷到 0x00。
5. **bcd_rollover**：预置 58 秒 59 分 09 时，等待两个真实 1Hz tick，验证 58→59→00 的 BCD 进位与分/时连锁。
6. **fast_mode_400k**：把 SCL 位宽从 10µs（100kHz）切到 2.5µs（400kHz），同样的写读序列在快速模式下全部通过。

## 关键结论（本次实测）

- 总线扫描 127 个地址仅 1 个 ACK、126 个 NACK，地址匹配与通用呼叫（0x00 不在扫描内）之外的静默行为符合 DS3231 从机模型。
- 写事务的首字节是**寄存器指针**而非数据；一次写多字节后指针停在最后地址的下一格，读事务前必须重设指针——重复 START 保留指针、STOP 也不复位，这是驱动里最常见的读回错误来源。
- 温度寄存器 0x11/0x12 的写操作被从机忽略，读回保持复位值（30.00°C 的 0x1E/0x00）；指针在 0x12 之后自增回卷到 0x00，突发读可以直接从温度寄存器绕回秒寄存器。
- BCD 走时实测：58s59m09h 经两个 tick 后为 00s00m10h，秒→分→时的半字节进位链正确。
- 同一套序列在 100kHz 与 400kHz 下行为一致；本测试台验证协议与寄存器语义，不检查 tSU/tHD/tLOW 等电气时序合规。

## 模型边界

- 从机是行为模型，不模拟 SCL 时钟延展、毛刺滤波、掉电切换（VCC/VBAT）、闹钟与中断输出、温度转换周期和 32kHz 输出；这些主题需要单独的测试台。
- 1Hz tick 是理想秒脉冲，不模拟 DS3231 的 ±2ppm 温补精度和老化漂移；ppm 级走时误差应查 datasheet 的精度曲线。
- 总线无噪声注入，ACK/NACK 均为确定性结果；多主机仲裁不在本实验范围内。
