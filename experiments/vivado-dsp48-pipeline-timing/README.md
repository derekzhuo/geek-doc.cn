# vivado-dsp48-pipeline-timing

**对应教程**：<https://geek-doc.cn/fpga/intermediate/vivado-dsp48-pipeline-timing.html>（随对应教程上线后生效）

比较同一组 16×16 有符号乘法在 0、1、2、3 级额外流水寄存器下的功能延迟、DSP 用量和实现时序。四档使用相同输入位宽、输出位宽、器件和 4ns 时钟约束。

## 复现（Windows，Vivado/XSim 2017.4）

```powershell
powershell -ExecutionPolicy Bypass -File run-dsp.ps1
```

脚本先编译四个模块和测试台，再分别执行综合、优化、布局和布线。固定器件为 Artix-7 `xc7a35ticsg324-1L`，工具路径在脚本顶部，按本机安装位置修改。

测试台先送四拍零输入填满流水，再施加 256 拍有符号伪随机激励。参考结果按各档延迟分别排队，在同一时钟沿后逐拍比较；任何错位或数值差异都会 `$fatal`，全部一致才输出 `DSP_PIPE_EQUIV_PASS cycles=256`。

实现阶段将四档资源及时序报告收进 `dsp-results.zip`。输出寄存器 `y` 标记 `DONT_TOUCH`，防止所有寄存器都被 DSP 吸收；`keep` 不足以阻止这种吸收。资源和 WNS 只适用于这个简单乘法 datapath、该器件及工具版本，不能直接外推为任意 DSP 设计的收益；增加级数也会相应增加结果延迟。

## 本次实测（2026-11-22）

四档 256 拍延迟对齐比较均通过。每档均使用 1 个 DSP48E1、0 个 Slice LUT 和 32 个 Slice Register；这 32 个外部寄存器是保留下来的 `y`，中间 `p0/p1/p2` 则映射到 DSP 内部流水寄存器。

| 额外流水级数 | WNS（ns） | WHS（ns） | 关键路径 |
|---|---:|---:|---|
| 0 | NA | NA | 只有外部输出寄存器，没有寄存器到寄存器路径 |
| 1 | 0.681 | 0.649 | DSP 的 `p0_reg` 到外部 `y_reg` |
| 2 | 2.511 | 0.300 | DSP 的 `p1_reg` 到外部 `y_reg` |
| 3 | 2.511 | 0.300 | DSP 的 `p2_reg` 到外部 `y_reg` |

1 级到 2 级时，关键路径从 DSP 乘法级输出转为 DSP 最后一级流水寄存器输出，WNS 因而改善；2 级到 3 级没有再改善，说明额外一级只增加结果延迟，并未改变这条关键路径。0 级的 NA 不是无穷大裕量，不能与数值 WNS 直接排名。所有数值均来自 4ns 时钟约束下的布线后报告，不包含输入/输出延时，也不代表板级接口时序。

公开日志已用 `<workdir>` 和 `<host>` 替换原始工作目录与主机名，未改动仿真结果、报告数值或诊断内容。
