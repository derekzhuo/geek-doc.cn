# chip-ref-attiny85：XSim 实测内部 RC 振荡器与 OSCCAL 校准对软件 UART 波特率的影响

**对应教程**：<https://geek-doc.cn/chip-design/chip-ref/attiny85.html>

## 复现方式

需要 Vivado Simulator（本实验用 2017.4，Windows）：

```bat
xvlog tb_attiny85_rc_baud.v && xelab -debug typical tb -s sim_attiny85 && xsim sim_attiny85 -runall
```

仓库内 `xsim-rc-osccal-baud.log` 是本次实测的原始输出（六场景 6 行 MEAS 记录）。

## 实验设计

ATtiny85 没有硬件 USART，无晶振方案下软件 UART 的位宽只能取整 CPU 周期，唯一时间基准是内部 8MHz RC 振荡器。测试台把波特率误差拆成两个来源分别测量：

- **整周期量化**：115200 波特的理想位宽是 69.444 个 CPU 周期，固件只能选 69 或 70；9600 波特对应 833.33 周期，取 833。
- **RC 振荡器漂移**：模型参数取未校准 ±10%、工厂校准 ±1% 两档精度边界；OSCCAL 为 8 位 trim 码，模型按每 LSB 0.5% 标称频率、工厂码 128 建模。
- 位周期用 32 个 bit tick 的平均实测量化，与 `chip-ref-atmega328p` 实验同一方法，两实验可互相校验。

六个场景各出一行 MEAS：

1. **bitbang_quant**：零漂移下 69/70 周期两档的实际波特率与量化误差。
2. **uncal_worst_115200**：±10% 漂移对照中点采样理论极限 ±5.263%（9.5 位帧留 0.5 位余量）。
3. **factory_cal_115200**：±1% 漂移对照 ±2% 常用工作窗。
4. **osccal_sweep**：256 个 trim 码全扫描，统计落进两个窗口的码数。
5. **trim_back**：±10% 最差个体遍历 trim 码找最近码，看能否拉回 ±2% 内、残差多少。
6. **baud9600**：低波特率下量化误差与 RC 漂移各自的表现。

## 关键结论（本次实测）

- 零漂移时 69 周期档实测 115994.6 baud（+0.690%）、70 周期档 114336.8 baud（−0.749%），软件 UART 光量化就吃掉约 ±0.7% 误差预算；32 bit 平均法带约 1/32 周期（≈0.05 个百分点）的测量粒度，两档结论不受影响。
- 未校准 ±10% 漂移下实测 +10.759%/−9.379%，两个方向都越过 ±5.263% 采样极限（fail=2）——无校准的 RC 直接跑 115200 必然丢帧，这不是软件能补的。
- 工厂校准 ±1% 档实测 +1.697%/−0.317%，压在 ±2% 工作窗内（pass=2），115200 可用但余量不大。
- OSCCAL 全 256 码扫描：只有 **8 个码**落进 ±2% 窗、**21 个码**落进 ±5.263% 采样极限，trim 分辨率（0.5%/LSB）决定了校准后残差不可能低于约 ±0.25%。
- ±10% 最差个体都能被 trim 拉回：正向漂移最近码 107、负向 147，残差均为 0.186%（trim_ok=2）；模型的 trim 量程（约 ±63%）远大于 ±10% 未校准偏差，瓶颈是步进分辨率而不是量程。
- 9600 档量化误差降到 0.044%，但 ±10% RC 漂移仍是 +10.048%/−9.960% 照样越限——**降波特率只能消除分频量化，消不掉振荡器本身的漂移**；工厂校准档 ±1% 在 9600 下实测 +1.045%/−0.956%，全绿。

## 模型边界

- RC 振荡器精度（±10%/±1%）与 OSCCAL 每 LSB 0.5% 的步长系数是**模型参数**，用于演示误差预算与 trim 量化机制；成稿引用具体精度数字与码值分布前，须对照 ATtiny85 数据手册的振荡器规格与 OSCCAL 校准曲线复核。
- 模型不含温漂、压漂（VCC 变化）、老化、片间分布与抖动，trim 曲线按线性建模；真实器件的单调性拐点与非线性需实测或查手册曲线。
- 软件 UART 部分只建模位定时，不含中断响应抖动、指令周期抖动与 GPIO 边沿斜率；接收机侧的采样架构影响见 `chip-ref-ch340g` 与 `chip-ref-cp2102` 两个链路预算实验。
