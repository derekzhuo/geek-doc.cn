# fio 扫档：块设备队列深度 iodepth 怎样换吞吐与延迟

**对应教程**：https://geek-doc.cn/concepts/storage/linux-blk-mq-iodepth-scaling.html （随站点发布生效）

在一台 2 vCPU / 8 GiB 的云上虚拟机（virtio 单硬件队列、mq-deadline 调度器）上，
用 fio + libaio 对 4K 随机读做 iodepth = 1/2/4/8/16/32 扫档，每个档位三轮，
观察吞吐饱和点与饱和后尾延迟的变化。

## 目录结构

| 文件 | 作用 |
|---|---|
| `iodepth.fio` | fio 作业文件，队列深度由环境变量 `IOD` 注入（fio 3.28 不支持 `--VAR=value` 覆盖） |
| `run.sh` | 三轮 × 六档扫档，逐档输出 JSON 并汇总 IOPS 与分位延迟 |
| `results/iodepth-r*-d*.json` | 18 份 fio 原始 JSON |
| `results/summary.csv` | 各档三轮中位数/最小/最大值汇总 |
| `results/rerun-header.log` | 内核版本、调度器、硬件队列数与 fio 版本记录 |

## 复现方式

```bash
# 需要 libaio 引擎与一块可压测的磁盘/文件；不要在系统盘关键数据上跑
fio --version          # 实测版本 fio-3.28
bash run.sh
```

## 关键结果（本机实测，不同云盘规格数值不同，趋势可对照）

| iodepth | IOPS 中位数（三轮区间） | clat p99 中位数 | clat p99.9 中位数 |
|---|---|---|---|
| 1 | 1664.6（1136–2307） | 2.18 ms | 14.75 ms |
| 2 | 3253.3（2389–3566） | 2.24 ms | 14.61 ms |
| 4 | 3854.8（2459–6075，突发信用期波动大） | 3.16 ms | 17.43 ms |
| 8 | 2460.0（2457–6053） | 6.65 ms | 19.27 ms |
| 16 | 2459.8（2460–2462） | 10.68 ms | 22.68 ms |
| 32 | 2459.5（2459–2460） | 17.43 ms | 28.44 ms |

云盘在 iodepth 4 附近吃到突发信用峰值，信用耗尽后吞吐回落到约 2460 IOPS 的
QoS 平台；平台期继续加深队列只推高尾延迟，不再换来吞吐。

## 测量口径

- 每档独立三轮取中位数，误差线保留最小/最大值，突发信用的不稳定性不做平滑；
- 直接 I/O（`direct=1`）绕过页缓存，测的是块设备与云盘 QoS 的行为；
- 单任务 libaio，`numjobs=1`，排除多任务互扰，纯看队列深度的作用。
