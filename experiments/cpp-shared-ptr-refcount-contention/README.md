# shared_ptr 原子引用计数争用：线程扫档实测

**对应教程**：https://geek-doc.cn/concepts/cpp-perf/cpp-shared-ptr-refcount-contention.html （随站点发布生效）

同一个 400 万任务的固定工作量，在 1/2/4/6/8/12 线程扫档下比较四种所有权模式，
把 `shared_ptr` 引用计数的原子操作成本与核间争用变成可复现的数字。

## 目录结构

| 文件 | 作用 |
|---|---|
| `payload.hpp` | 每任务 64 轮乘加的固定工作量对象 |
| `main.cpp` | 四模式 runner、线程扫档、预热与 checksum 防消除 |
| `Makefile` | `bin/bench` 单一目标（`-O2 -std=c++17 -Wall`） |
| `run.sh` | 7 次运行按格取中位，并从反汇编统计 lock 前缀原子指令 |
| `results.txt` | 一次完整运行的实测输出 |

四种模式：

1. `unique`：每线程独占 `unique_ptr`，无共享所有权流量；
2. `raw`：只读裸指针共享同一对象，无原子操作；
3. `shared_ro`：`shared_ptr` 每线程启动时拷贝一次，任务循环不碰引用计数；
4. `shared_copy`：每个任务拷贝一次 `shared_ptr`，每任务两次原子操作（析构配对）。

## 复现方式

```bash
make
bash run.sh
```

## 实测结果（Apple clang 21.0.0，-O2，macOS，6 大核 + 6 小核，2026-11-11）

| 线程数 | unique (ms) | raw (ms) | shared_ro (ms) | shared_copy (ms) |
|---:|---:|---:|---:|---:|
| 1 | 12.842 | 12.943 | 11.226 | 68.111 |
| 2 | 6.551 | 6.426 | 5.643 | 229.535 |
| 4 | 3.295 | 3.430 | 2.890 | 238.282 |
| 6 | 2.272 | 2.457 | 2.003 | 239.667 |
| 8 | 2.504 | 2.319 | 2.182 | 250.324 |
| 12 | 2.157 | 1.894 | 1.899 | 221.887 |

前三种模式随线程数近线性加速（12 线程约 6 倍），`shared_copy` 单线程就慢约 5 倍，
多线程下不降反升、加速比仅 0.27–0.31。反汇编可见 7 条 `lock xaddq`/`lock incq`
原子指令，即引用计数增减落在同一条缓存行上的核间乒乓。
